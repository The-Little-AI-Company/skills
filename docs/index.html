Design review

Statechart Design and Review

Published source

Open skill instructions · Read Markdown entry

What

The agent lists events, guards and actions, separates state from data, states invariants, builds a transition table, writes counterexample traces and proposes tests.

A Mermaid diagram shows structure only. It does not execute semantics.

When to use

Use for complex event-driven lifecycles with nesting, concurrency, cancellation, recovery or stale completions.

Do not use for trivial flags without lifecycle complexity.

Installation

Copy the whole folder skills/design/statechart-design-review into the agent's existing skill directory. Do not copy the collection root as one skill. Do not install dependencies.

The existing skills tool may support: skills add The-Little-AI-Company/skills --skill statechart-design-review. No new tool install is needed. The manual folder copy is the documented path.

Python 3.10 or later and the standard library are needed for the bundled tools.

Run commands from the chosen skill folder.

python scripts/check_inventory.py examples/minimal-inventory.json
python -m unittest discover -s tests -p "test_*.py" -v
python tests/export_safety_test.py

Example

Synthetic teaching scenario, not a verified defect in any real product. An export is cancelled before a late completion arrives.

Ask the agent for the forbidden publication trace, the guard that blocks it, and a regression test.

Limits

The structural inventory linter is not proof of behavior or determinism.

The synthetic model excludes persistence, a durable outbox, networks, restart, real timing, runtime priority and liveness.

Some failure and pending events lack generation IDs.

There is no claim that every stale event is safe.

No agent effectiveness or real project benefit has been measured.

Evaluations

Rerun on 2026-10-03: 5 inventory tests, the minimal inventory check, 14 named safety traces and 262144 length-six event sequences passed.

These are bounded synthetic checks. They do not establish agent effectiveness or behavior in a production application.

Recovery checks

Resume drift check

Published v0.3.0

Open skill instructions · Read Markdown entry

What

Compares claims in a saved checkpoint against observations the operator supplies. Prints an advisory report.

Creates no checkpoint store and collects no live data. Supplied evidence can be wrong or stale. Time and source labels are not authentication.

Claim kinds: head, tree, test, action, process, approval, capability. Missing evidence is never a match.

Labels: MATCH, DRIFT, STALE, UNKNOWN, DO_NOT_REPEAT. A completed or uncertain action stays on hold. Unrelated observations cannot establish its outcome.

For a test, the exact subject defines its source scope. Exactly one valid, timely current head and tree observation must agree with the receipt before it can match. Missing or ambiguous source is UNKNOWN. A different source identity is STALE.

When to use

Use for a bounded resume decision when evidence is available.

Avoid trivial disposable tasks, automatic recovery, exactly-once execution and security guarantees.

Never use it to justify replaying an uncertain action.

Installation

pnpm dlx skills@1.7.0 add The-Little-AI-Company/skills --skill resume-drift-check --agent codex

Run the install command in the target project. Omit --agent codex for interactive agent selection. Alternatively, copy the complete skill folder into an existing skill directory.

The comparator requires Python 3.10 or later and no third-party Python packages.

The demo helper creates synthetic input files and refuses to overwrite existing ones. The comparator only reads them.

Run commands from the chosen skill folder.

python examples/make_demo.py
python scripts/drift_check.py checkpoint.json observed.json --format md

Example

Synthetic example. A saved HEAD differs from the observed HEAD and an action may have completed before the interruption.

The report shows DRIFT and DO_NOT_REPEAT with advice STOP_AND_VERIFY_OUTCOME. Verify the outcome through an authorized read-only observation. Do not repeat the action automatically.

Read the synthetic demo instructions.

Limits

Exit code 0 means every listed claim matched. Exit code 1 means any non-match. Exit code 2 means invalid input. An example that exits with 1 can be working as intended.

Supply local regular JSON files. FIFO, directory and device inputs are rejected. There is no hard filesystem latency guarantee. The Windows precheck/open race remains a documented limit.

An all-match result is advisory and never permission to act.

It reads only the two supplied files. It performs no mutation, subprocess, network call, cleanup, restart or action replay.

Manual evidence collection cost and adoption effort are unmeasured.

Context Continuity already has evidence-file hash checks, bound reviews, checkpoint chains and writer-lock liveness. The narrow hypothesis here is comparing task claims with supplied task observations. Three tools were compared. This is not an exhaustive market map.

Evaluations

Version 0.1.0: 25 contract tests passed. Initial held-out variations passed 7 of 8 and found an oversized-integer input error. After repair all 33 passed. The reused eight are regression evidence.

Independent review of 0.1.0 passed 33 suite tests and 20 independent CLI cases, then found a source-binding gap and FIFO hang through exploratory probes. That review held the candidate.

Version 0.2.0: 49 tests passed on 2026-10-03, comprising 25 contract, 8 earlier regression and 16 review regression tests. Both original review inputs now exit 1. With current head supplied, changed bytes mark the test STALE. The same reviewer passed 13 independent checks and 16 focused regressions for the two fixes.

The 11 bundled cases are synthetic. No agent-effectiveness, savings or market validation exists. Evidence-collection effort and real-world benefit remain unmeasured.

On Windows 11 with Python 3.14.3, 47 suite tests passed and the two POSIX FIFO tests were skipped. Thirteen additional Windows CLI checks passed. No path-replacement race or hard filesystem latency guarantee was tested.
